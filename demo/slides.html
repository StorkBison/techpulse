Resilient browser automation

@retry(
    retry=retry_if_exception_type(PlaywrightError),
    stop=stop_after_attempt(3),
    wait=wait_exponential(multiplier=1, min=1, max=8),
    before_sleep=before_sleep_log(log, logging.WARNING),
    reraise=True,
)
async def _scrape_page(self, page, n):
    await page.goto(f"{HN_BASE}/news?p={n}",
                    wait_until="domcontentloaded")
    await page.wait_for_selector("tr.athing")
    return await extract_stories(page)
  • Extraction runs in the page - one JS pass maps each story row to a typed record.
  • Exponential-backoff retries on timeouts and network errors.
  • Blocks images, fonts and CSS to cut bandwidth and time.
  • Same code path offline: a saved HTML fixture powers tests and CI.

Claude with schema-validated output

class StoryInsight(BaseModel):
    hn_id: int
    category: Category          # Literal[...] enum
    relevance: int = Field(ge=1, le=10)
    summary: str
    tags: list[str]

response = self.client.beta.messages.parse(
    model="claude-opus-5-5",
    system=SYSTEM_PROMPT.format(interests=...),
    messages=[{"role": "user", "content": payload}],
    output_format=InsightBatch,      # Pydantic schema

    betas=["server-side-fallback-2026-07-01"],
    fallbacks="default",

  • Structured outputs: the response is parsed straight into Pydantic models. No regex, no brittle JSON parsing.
  • One request per batch of 30 stories keeps cost and latency low.
  • Guards: refusal and truncation checks, hallucinated IDs filtered out.
  • Offline fallback: a deterministic keyword enricher runs when no API key is set.
Code · Reliability

Built to run unattended

techpulse/pipeline.py
async def run(self, trigger: str) -> Run:
    if self._lock.locked():
        raise PipelineBusyError("already running")
    async with self._lock:
        return await self._run(trigger)

# inside _run():
scraped = await self.scrape()
new = self._upsert(db, scraped); db.commit()
pending = select(Story).where(Story.relevance.is_(None))
run.enriched = await self._enrich(pending)
run.alerts = self._alert(db)   # alerted=False only
  • No overlapping runs - scheduler and API share one lock.
  • Idempotent: re-runs refresh points and comments without duplicates.
  • Self-healing: if the AI step fails, stories stay pending and are retried next run.
  • Every run is audited - counts, enricher, duration and error.
  • Blocking API calls run off the event loop.

Deploy

One command to production-like

terminal
cp .env.example .env    # add ANTHROPIC_API_KEY, SLACK_WEBHOOK_URL
docker compose up --build

# app  -> http://localhost:8000      (dashboard)
#      -> http://localhost:8000/docs (OpenAPI)
# db   -> PostgreSQL 16 with health check
docker-compose.yml
app:
  build: .
  environment:
    DATABASE_URL: postgresql+psycopg://techpulse:...@db/techpulse
  depends_on:
    db: { condition: service_healthy }
  • Non-root container with a HEALTHCHECK.
  • 12-factor config - everything comes from environment variables, validated by Pydantic.
  • SQLite for dev, PostgreSQL in Compose. Same code, swapped by URL.
  • Chromium baked into the image, so it scrapes anywhere.
